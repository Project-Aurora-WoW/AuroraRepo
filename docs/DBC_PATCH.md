не существуют для клиента. Серверная часть (`aurora_campaign01_achievements.cpp`)
готова и начнёт выдавать награды сразу после установки этого патча.

### Дубль 5005 и 180

Титул 5005 содержит то же имя, что и 180. Причина — два независимых источника:
`aurora_titles` ссылается на 5005, а серверный модуль наград за достижения
(`aurora_achievement_rewards`) на 180. Пока это разные записи, клиент показывает
разные названия; после решения, какой ID оставить, второй нужно убрать из
таблицы и патча одновременно.


## Установка

Заливать как патч клиента (MPQ), а не файлами в корень — клиент читает DBC только
из MPQ-архивов.

1. Распаковать `dbc/*.dbc` в отдельную папку.
2. Собрать MPQ-архив патчем: `patch-4.MPQ` (или следующий свободный номер).
   Инструменты: `MPQEditor` — создать патч-архив, добавить каталог `DBFilesClient`
   с тремя DBC внутри.
3. Положить архив в `Data/` клиента: `Data/patch-Z.MPQ` или следующий по порядку.
4. Всех игроков обновить одновременно — сервер и клиент должны видеть одинаковые ID.

Прямая копия DBC в папку клиента **не работает**: WoW 3.3.5a игнорирует файлы вне MPQ.

## Сервер

Сервер перезапускать не нужно — он читает DBC при старте. После первого запуска с
установленным патчем проверьте в логе:

```
[Aurora] Achievement <id> is not in Achievement.dbc
```

Этих строк быть не должно. Если они остались — патч не подхватился (неверный номер
MPQ или неполный `DBFilesClient`).

## Перегенерация

Скрипт `tools/aurora_dbc_patch.py` строит патч из базовых DBC. Путь к базовым
DBC задан константой `DBC_DIR` в начале файла.

```
python tools/aurora_dbc_patch.py
```

Скрипт идемпотентен по ID: уже существующие записи пропускаются с сообщением
`skip existing achievement <id>`. Коллизии ID проверяются после генерации
отдельным проходом по файлу — в самом скрипте этой проверки нет.

## Ограничения

- Записи добавляются **в конец** файла, порядок существующих не меняется.
- Русские имена и описания записаны в слоты `ruRU` (следующий слот после `enUS`:
  `row[5]` — название, `row[22]` — описание, `row[3]` и `row[20]` — титул мужской и женский).
  Заполнение подтверждено обратным чтением файла. Читает ли клиент эти слоты в
  `Achievement.dbc` — не проверено: ни у одной из 1817 штатных записей файла нет
  непустых слотов, кроме `enUS`, то есть примеров использования в файле нет.
- Категории достижений (ID 5, 10, 50) — штатные категории WotLK, отдельная
  вкладка кампании в окне достижений не создаётся: для неё нужен ещё
  `AchievementCategory.dbc` и правки UI, которых в патче нет.
- Иконки взяты из существующих SpellIcon — новых изображений патч не добавляет.


## Проверка из игры

Аддон AuroraUI проверяет патч прямо в игре: команда /aui patch.

Она спрашивает у клиента GetAchievementInfo для ID 10001-10099 и печатает:

- DBC-патч установлен: 15 из 15 достижений - всё на месте;
- DBC-патч неполный: N из 15, первое отсутствующее ID X - патч встал частично;
- DBC-патч не установлен - клиент этих достижений не знает;
- Проверка DBC недоступна - клиент не отдаёт API достижений.

Модуль: addon/AuroraDBC.lua, подключён в AuroraUI.toc раньше основного файла.

Разбор файла (AuroraDBC.ParseDBC) реализован полностью, но из игры вызвать его нельзя:
в 3.3.5a Lua не имеет доступа к файловой системе и MPQ. Функция нужна для отладки,
когда байты файла попадают в Lua иным путём.

## Что не проверено

- Синтаксис Lua интерпретатором не проверялся: на машине Lua нет, аддон в игре не загружался.
- Поведение GetAchievementInfo для несуществующего ID подтверждено только по описанию API WotLK, вживую нет.
